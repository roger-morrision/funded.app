# Shared Devnet RPC service

The app, browser RPC proxy, collector and automation workers use one private `rpc-gateway` service. Only the gateway mounts the configured Helius or public-RPC URL. Change `.secrets/rpc-gateway-upstream-url` to switch providers, then recreate the gateway. Never point that file at the gateway itself.

The gateway keeps one persistent provider HTTP socket and one serial request budget. Ordinary requests start at least 250 ms apart for a Helius host and 500 ms apart for other providers. Historical block reads remain at least 2.5 seconds apart; transaction submissions are separately paced at one per second. These Helius budgets stay below the documented [Free RPC limits](https://www.helius.dev/solana-rpc-nodes). Provider rate limits trigger a shared cooldown. An explicitly method-specific limit cools down only that method, so unrelated financial reads can continue. Health and metrics requests use local state and consume no provider requests.

Simultaneous identical reads share one upstream request. Compatible base64 account reads are grouped into one atomic `getMultipleAccounts` request, with the same commitment, encoding, data slice and minimum context slot. Each caller receives its original account and response ID. Batches are capped at the [Solana limit of 100 accounts](https://solana.com/docs/rpc/http/getmultipleaccounts).

Only network identity and non-null finalized transaction/block history are cached. Mutable balances, blockhashes, holder indexes and signature statuses are never served from a TTL cache. A transaction submission separates later readers from earlier in-flight reads. Submissions and simulations are never cached, deduplicated, automatically retried or replayed to another provider. Existing application receipt/reconciliation guards remain active.

## Redis history cache

`FUNDED_RPC_REDIS_URL` enables a shared Redis L2 behind the gateway's bounded in-memory cache. Explicitly finalized, non-null `getTransaction` and `getBlock` results remain reusable for 24 hours, including after a gateway restart. The in-memory history TTL remains five minutes and never extends the original Redis expiry. Request keys include every RPC option, use a SHA-256 digest and are namespaced by cache schema and Devnet genesis. Each gateway still checks the actual upstream genesis at startup; Redis cannot establish network identity.

Mutable token/account state, balances, prices, blockhashes, signature statuses, confirmed history, nulls, RPC errors, simulations and submissions never enter Redis. This preserves the freshness of payment and eligibility checks. A later transaction does not invalidate already finalized immutable history. Only immutable results enter Redis, so no distributed write-invalidation protocol is needed.

The official Node Redis client has offline queuing disabled, a bounded command queue and reconnect backoff. Cache reads and writes have an explicit 200 ms response deadline as well as the client queue timeout. Late responses are ignored. An unavailable or malformed cache falls back to the existing RPC queue; expired data is never served. Redis failures trigger a five-second local cache backoff. `/metrics` includes `redisCacheHits`, `redisCacheErrors` and a `redis` object with readiness, read, hit, write, error and rejected-entry counts. It does not expose cache keys or credentials.

The compose overlay and staging helpers add `rpc-cache` on an internal network joined only by the gateway, without a host Redis port or signing/provider secrets. Redis uses a 128 MiB LRU cache and a persistent AOF volume. Losing that volume loses cached public history only; it does not affect financial receipts or application records. The default `redis:8-alpine` image resolves to the digest recorded at deployment.

For a gateway-only release, build `Dockerfile.rpc-gateway` with the exact `FUNDED_SOURCE_REVISION`, tag it `fundedapp-devnet:rpc-cache-<first-eight-sha>`, then run `node scripts/stage-rpc-cache.mjs --revision=<tested-sha>`. Apply its staged compose file to `rpc-cache rpc-gateway` only. This preserves the running app, worker images, frontend mount and financial settings. No contract upgrade is required.

Run the focused tests with `node --test tests/redis-rpc-cache.test.mjs tests/rpc-gateway-redis.test.mjs tests/rpc-gateway-config.test.mjs`. For a disposable real Redis instance, set `FUNDED_TEST_REDIS_URL` and run `node --test tests/redis-rpc-integration.test.mjs`; it checks actual Redis persistence across clients, server TTL, a stalled command deadline, fallback and recovery with a local RPC fixture. No Helius call or transaction is made by that integration test. The gateway-only image includes the official [Node Redis client](https://redis.io/docs/latest/develop/clients/nodejs/produsage/).

The active Redis rollout, measured repeat-read savings and restart verification are recorded in [November 1 Redis acceptance](devnet-redis-cache-2026-11-01.md). The later financial-flow acceptance is recorded [separately](devnet-helius-e2e-2026-11-01.md); the initial deployment below is historical.

Browser signature subscriptions pass through `/api/solana/ws`. Internal SDKs use the private WebSocket port 8900. The gateway polls unique signatures together over its existing HTTP transport; it does not open a provider WebSocket. Only transaction-signature subscriptions are supported. Origin checks, bounded subscriptions and the existing public HTTP rate limits remain in place.

Use `compose.rpc-gateway.yml` after the normal app/collector/agency overlays, or run `node scripts/stage-rpc-gateway.mjs --revision=<tested-sha>` against the existing deployment. The staging helper preserves financial policies and removes provider secret mounts from the clients. Start the gateway first, confirm Devnet and the pinned program hash through it, then switch the app and workers. `scripts/stage-automation-services.mjs` preserves central routing on later releases.

Local tools can use `http://127.0.0.1:8899` and `ws://127.0.0.1:8900`; both host ports bind only to loopback. Provider credentials remain inside the gateway. Metrics at `/metrics` expose request, upstream, cache, coalescing, atomic-batch, queue and cooldown counts without addresses, signed transactions or credentials. Request-count savings do not by themselves measure a provider's billed credits.
