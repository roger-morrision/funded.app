# richpad.fun nonprogram site release

This is a site release for the existing `richpad-mainnet` service. It does not deploy, configure, or activate the ExUNA fee router. `scripts/mainnet-nonprogram-site-plan.mjs` is a local dry-run gate; its output is deliberately non-executable. Use it only after collecting fresh sanitized current and candidate inventories from the actual host and reviewing the full Compose diff.

## Release procedure to implement and review before execution

1. Collect fresh current inventories immediately before deployment: finalized genesis, public HTTPS identity and frontend hash, full image digests for all five services, Compose hash, public policy flags, container IDs and health, backup and free-space status. Never capture secret values in a release report.
2. Build a candidate from the exact integrated Git commit with complete source, immutable image digest, revision label, frontend asset hash and Compose file hash. Review its Compose diff. Only the app and RPC gateway image/build identities may change; service definitions, mounts, secrets, policy, ports and dependencies must remain fixed. The current nonprogram mint and fee policy are pinned by this gate.
3. Run the dry-run checker with sanitized `current.json` and `candidate.json`. Inspect the output and independently compare every value to the actual host and build. The checker cannot authenticate its input or prove the candidate image contains the stated source.
4. Retain the old image, Compose file, source and backups. Under an exclusive release lock, compare the remote state again; abort on drift. A separately reviewed executor may switch **only** `app` and `rpc-gateway` with Compose `--no-deps --no-build --pull never`. It must check the Compose exit status. Do not run the historical ignored `tmp/mainnet-deploy/ship.sh`: it uploads secrets, may recreate dependencies, masks Compose failure and prunes old release material.
5. Verify both containers healthy and public HTTPS build revision, frontend hash, cluster, genesis, mint, fee policy and activation state after the switch. On mismatch, preserve the failed candidate and reconcile observed container/image state before restoring the exact retained old revision. Do not trigger worker or financial canaries as part of a site-only switch.

The current code supplies the dry-run gate and procedure, **not** the remote executor or a candidate image. A live release still needs a fresh candidate build, exact current-state capture, reviewed Compose diff, serialized switch/rollback implementation, and independent post-switch checks. Pushing `main` runs repository CI checks; no automatic richpad.fun deployment was established from the checked-in workflow or historical Render configuration.
