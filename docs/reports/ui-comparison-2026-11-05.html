Keep Home short, give every task one clear entry point, and show verified amounts with their receipts. Adopt useful competitor patterns while keeping funded.vip’s own identity and transaction safeguards.

Scope and evidence

The review covered 25 funded.vip routes at 1440px and 390px, plus Welcome, token detail, creation step two, wallet connection and legal dialogs. The initial route inventory found no page-level horizontal overflow or JavaScript errors. Wallet approval, successful payments, protected admin data and completed on-chain launches were not established by this visual review.

Local evidence: tmp/site-comparison/funded/inventory.json and screenshots in tmp/site-comparison/. These temporary artifacts are not included in the repository. Automated UI fixtures use mocked data; they do not establish live balances or transaction success.

Changes included in this release

  • Home: compact verified activity strip alongside the short overview and primary actions. Removed the separate “Start with a coin” search panel.
  • Explore: removed the requested quick-buy input and tightened the responsive control grid.
  • Token detail: About/Updates in the header, a rewards dashboard/table, and one Post button. Server-verified holders create calls when market data and call limits permit; other posts remain chat.
  • Create: visible description, cleaner steps, less duplicate cost text, “Sign & approve,” a busy state during creation, and a success dialog after verified completion.
  • Metadata: accept verified Pinata publication, use the exact IPFS content address in the transaction, and retain public image/JSON checks and exact metadata matching.
  • Portfolio and Rewards: tracked-wallet/favorite-coin tabs, compact coin identity in reward clocks and payout receipts, and “Coin Holder” wording.
  • Welcome: remove the duplicated fee-flow diagram; show 1% referral rewards and the 2% AI/coin-buyback allocation in a balanced six-card layout. Funding and milestone conditions remain explicit.
  • Service status moves into the admin workspace. Listing lookup distinguishes a missing Devnet mint from an unsupported token account.

Latest implementation

Home now includes a manual Trending strip, six newest image-led token cards, the six community benefit cards, and the FAQ banner. The duplicate search panel and first-visit guide are removed. Token holder rewards sit at the bottom of the token page; Price displays the spot price. Launch packages show the wallet-scoped $FUNDED balance directly below the package choices. Portfolio includes tracked wallet cards, My rewards and My referral tabs, with duplicate header shortcuts removed.

Holdings reads have a bounded foreground budget and one transient retry per token program. Signed launches verify exact message bytes and every required signature regardless of wallet SDK wrapper type. Chat posting reports whether a call was recorded or why it remained chat; holder detection uses raw token amounts. These changes do not turn unavailable data into zero or authorize transactions.

Release validation boundaries

Automated checks cover responsive layout, keyboard navigation, mocked reward/portfolio states, launch cost presentation, call eligibility, metadata integrity and atomic packet size. Live release verification must additionally match the source revision, frontend artifact and all four application services. No signed-out browser check proves a real buy, burn, launch, payout or claim.
