# X-linked creator fee claims (Devnet)

This route is **off by default**. Historical launches using the shared `funded-fee-router-v1` PDA cannot produce an X obligation: Pump creator-fee collections from that address are not attributable to one mint.

As of 2026-09-29, the existing Devnet program already executes `InitializeMint` and `SettleMint`; a binary upgrade was unnecessary. A finalized transaction (`3UejTrCdTGDUAvau2rMzXjR64zv5PqUT3pajpajVSwRU6aTh9Aoj7qJ15kYNC7wf8U4UTxhwMyxX96v1pjY9ERfY`) created a mint router and claim PDA and paid an in-memory test recipient exactly 1,000,000 lamports. The legacy router header, program-data hash, claim record, and recipient delta were verified. The funded.vip Devnet deployment enables the mint-router gate; historical shared-router launches remain ineligible for X claims. That September test did not verify a real X OAuth sign-in, wallet binding, Pump fee collection, and user claim end to end; the later paid recipient evidence is recorded below.

For a new X-linked launch, the wallet initializes a PDA seeded by `funded-mint-router-v2` and the new mint, and Pump records that PDA as the fee owner. The backend verifies the Pump creator, collects to that PDA, reads the confirmed transaction's router balance delta, and calculates the X share from the immutable launch policy. The X account must sign in through OAuth and sign a wallet-binding message; the first verified wallet cannot be changed. Settlement uses the router program's `settle_mint` instruction and a mint-scoped on-chain claim PDA, so retrying cannot pay twice.

Before enabling:

1. For a future bytecode change, build with an SBF toolchain supporting Rust 2024 dependencies, for example `cargo build-sbf --manifest-path programs/funded-fee-router/Cargo.toml --tools-version v1.53` from `contracts/funded-fee-router`. Local `cargo check` alone is **not** a deployable `.so`.
2. Upgrade the existing Devnet program ID only when the deployed bytecode lacks the required instruction or a reviewed code change requires it. Keep the existing upgrade authority and program ID, and verify the deployed code and legacy router header on-chain.
3. Configure `FUNDED_ROUTER_AUTHORITY_KEYPAIR_PATH` with the keypair matching the authority in the legacy router header. This is a server-only settlement key; never use a `VITE_*` variable or paste it into chat.
4. Configure `SOLANA_KEEPER_KEYPAIR_PATH`, `SOLANA_KEEPER_CONFIGURED=true`, and fund that dedicated Devnet keeper for transaction fees. Configure `X_CLIENT_ID`, `X_CLIENT_SECRET`, `X_BEARER_TOKEN`, and the exact `X_CALLBACK_URL` in the X developer app. For the existing Devnet Compose stack, include the ignored `.env.x` after `.env.deploy` in every app recreate command, for example `docker compose -f compose.preview.yml -f compose.funded-vip.yml --env-file .env.deploy --env-file .env.x -p fundedapp up -d --no-deps --no-build app`. The bearer token resolves the launch handle to X's stable user ID before any coin transaction is sent; payouts are bound to that ID, not a mutable handle.
5. Run `npm run verify:mint-router-v2`, `npm run verify:x-fee-server`, `npm run verify:launch-wizard`, and `npm run build`. Perform a Devnet-only end-to-end launch, fee collection, X OAuth, wallet signature, and settlement with ephemeral test identities and verify on-chain balance and claim-account deltas.
6. Set `FUNDED_MINT_FEE_ROUTER_ENABLED=true` only after the on-chain router and settlement checks. The frontend reads `/api/x-fee/status` and blocks X shares when a configured prerequisite is missing. Keep actual claims under review until the X identity, wallet binding, fee collection, and payout receipt are jointly verified.

The authenticated keeper calls `POST /api/keeper/collect` with the mint. A successful mint-verified collection creates the obligation automatically. The signed-in X user sees it in `/api/x-fee/claims` and can complete the claim in the app. The route does not claim that the other 80/20 policy destinations are already distributed; those obligations need their own verified settlement flow.

## Devnet X claim QA target

Keep `X_TEST_HANDLE`, `X_TEST_WALLET`, `X_TEST_MINT`, `X_TEST_PAID_LAMPORTS`, `X_TEST_PAYOUT_SIGNATURE`, `X_TEST_RPC_URL_FILE`, and `UI_BASE_URL` in ignored `.env.x-claim-qa.local`. `npm run verify:x-claim-target-devnet` checks public X lookup, claim readiness, anonymous claim privacy, fee allocation, and finalized payout balance deltas without signing or submitting a claim. `npm run verify:x-claim-ui-devnet` checks paid, pending, available, sign-out, and unavailable states in a browser with mocked claim APIs. The public wallet address is an expected recipient, not a signer or a wallet binding override. Actual account sign-in and a new wallet signature require the account holder in the app.

On 2026-10-10, the existing `@JohnTrand83` obligation for mint `7cuCDDa6e5Jx1gvxwTug5zhDE82L4HoTRnR1KTB7R4CA` showed 187,844 lamports allocated and paid. The finalized transaction `4Fe45BeoYCzkZvvnywYnqUmbvLghVG9NXsVdwhT9THLpc2ZttF4sgwWSpu82FFJ6iW4d84gUje6Y6Hde8ZTNJ1dZ` increased `ER7zhtSwfSu7B5Wb7uFwnWSZPLMmezmSXieY5JyLFzXC` by exactly 187,844 lamports. This paid obligation cannot be claimed a second time; create a separate eligible Devnet collection to exercise a fresh user signing flow.

On 2026-10-12, a new disposable X claim QA mint `4rgB6cD9voLGCjMdCG5c9FtD9YrXqHJVgatKp2ps5Xih` was registered with the stable X user ID `2076871542202638336` for `@JohnTrand83`. Its Pump launch `4ieCLziNEwjBE2cmVH6Zm9WaNzL31JQpxN5yYX6kTxEJ15QbtW3T7WpW1XUCZaCRY1hvP2LvebPhFeNdrdvnEYPx`, buy `L6FCBq8LdZUmWGsacNmMHgZKAzE8tNRt9W5aXTxd83b3vcHekUVvanWEm6Miq1ga9CVmiAoefXPXmrrKQpfXB7R`, and fee collection `4xchUGEXFqQTC8PAV6aiD7NKVEUa8Zgoi3RSsApRdESgZs6X8wjbYuhAHEcYwyvGEkahP3wBPxQjJRLNvh1so826` were independently confirmed finalized with no errors. The public fee ledger records 187,844 lamports allocated to X and zero paid. `npm run verify:x-claim-target-devnet` passed with the consenting recipient wallet. This verifies allocation and claim readiness, not account sign-in, wallet ownership, or a new payout. The recipient must complete X sign-in and a wallet-binding signature; the dedicated QA creator must then approve settlement.

For a fresh claim QA mint that will need creator approval after the launch script exits, set `X_TEST_QA_CREATOR_PAYER=true` when running `scripts/create-devnet-x-claim-obligation.mjs`. This uses the existing dedicated Devnet QA creator signer after matching its public key to the QA manifest. The default remains an in-memory ephemeral creator. Never use the dedicated QA signer for a production launch.
