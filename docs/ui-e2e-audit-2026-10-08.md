## Recommended next improvements

1. Label unavailable Portfolio token identities clearly and resolve the known $FUNDED identity instead of repeating an address.
2. Paginate Created tokens and reward history for wallets with many launches.
3. Keep eligibility, amount and the next action visible; use expandable details for addresses, coverage and verification.
4. Measure onboarding completion and confirmed transaction conversion with the approved opt-in anonymous journey counts. Do not infer user growth or volume from UI changes alone.

## Follow-up: histories, token identity and referral labels

Implemented ten-item pagination for holdings, trade activity, Created tokens, Creator rewards, reward history, payment history and referral history. Controls show item/page counts, clamp when data shrinks, preserve the current page on refresh of existing lists, and reset on wallet or filter changes. Aggregate balances still include all records. Pagination covers the loaded records; it does not expand backend history coverage.

Portfolio resolves the configured $FUNDED mint and available launch names. Missing names use an explicit Unnamed token label and retain a shortened address with the full address available. Referral summaries distinguish connection, verification, loading, unavailable and claimable states; internal claim statuses use readable labels.
