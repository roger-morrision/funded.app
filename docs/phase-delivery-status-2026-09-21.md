## Release and operational requirements

1. API/frontend now deployed together at Docker origin port 8788: `/api/capabilities.version` is `creator-support-v10`, build `creator-support-v10-20260921a`. The independent Vite preview on 5174 was not restarted. Authenticate through Cloudflare Access to verify the public ingress; do not treat an Access HTML response as API success.
2. `PUBLIC_APP_URL` and `CORS_ORIGIN` are set to the approved `https://funded.vip` in the release overlay, without changing local Vite settings. This PC/tunnel is still not durable hosting. No request Host or credentials are reflected into the image URL. Social crawlers currently encounter Access; access-policy changes need separate authorization.
3. Keep same-origin `/api` routing and exact `CORS_ORIGIN` behind a proxy. Verify rate-limit behavior through the actual ingress; the default socket-based creator read budget is shared when a proxy hides client addresses.
4. Run `npm.cmd run verify:release-contract` with `FUNDED_RELEASE_BASE` pointing at the intended tested Devnet release. A green response proves contracts/assets only, not on-chain settlement.
5. Supply approved Devnet identities/authority custody and complete confirmed state/balance-delta tests before activation. Do not use production or real-user keys for QA. Do not enable mainnet on the strength of local or mocked checks.
6. Select and review approved gifting, durable hosting/metadata and notification providers before external integration. Sessions now use the existing PostgreSQL store; configure and review its operational protection. Do not manufacture fallback transfers or gifts.

Safe local configuration inspection in v5 found `DATABASE_URL` present, but `PUBLIC_APP_URL`, `CORS_ORIGIN`, `X_CALLBACK_URL`, X client ID/secret, keeper secret and router-authority secret absent. Only presence booleans were inspected/reported; values and private keys were not displayed. Provider setup and authority custody still require operator configuration, not invented credentials.

Receipt reads no longer hydrate the entire PostgreSQL ledger. Exact eligible-record counts use transactional keyed counters; ordinary creator snapshots still grow with that creator's history. X-claim transitions, referral verification/execution transitions and creator-profile writes now use scoped paths; collection, settlement, entitlement creation and referral preparation still use the legacy ledger transaction. History hydrates only one page and referenced records; visibility checks still read that creator's launch policies. File fallback remains single-process with whole-file persistence.

Recent evidence remains confirmed and cached for up to 30 seconds. History is separately finalized and persists successful proofs in `receipt_proofs` (file fallback: `receiptProofs`). Canonical fingerprints include the whole source record, so edited records need new proofs; current entitlement and privacy checks are still required. A separately enabled worker can sweep registered collection/payout records in bounded leased batches; it is disabled in the deployment and does not discover unknown chain transactions. No complete-chain coverage guarantee or lifetime earnings total exists. Keyset browsing is not one snapshot spanning all pages; changed/new records can require Start over. Old fingerprint versions remain stored. V9 supplies bounded dry-run/apply tooling, but an operational retention policy and archive-RPC review are still required.

## Deliberately not represented as complete

Complete lifetime payout coverage and full-chain discovery, backfill worker activation/monitoring, managed hosting migration, durable public metadata guarantees and authenticated deployed session verification, moderated chat, email/push notifications, streaming gift delivery/refunds, creator recruitment, economic experiments, localization research, independent reviews, mainnet production launch and measured adoption/virality. Vanity inventory, extra chains, LaunchLab expansion and changed referral economics remain deferred by the original roadmap, not silently introduced.

Launch keys are intentionally not saved. After a reload during an unsigned or router-only stage, there is no automatic continuation requiring that lost mint key. Inspect the original receipts; never assume a network timeout means failure. Journal confirmation is transaction-level evidence, not a fee-policy verification or completed registration.
