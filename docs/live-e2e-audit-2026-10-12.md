## Public browser evidence

`scripts/verify-funded-vip-live-browser.mjs`, with the QA mint and wallet supplied through environment variables, checked 24 routes, three legal dialogs, 27 selected tabs, 16 selected toggles, and 67 filter selections. Home search narrowed the QA mint to one verified coin and Reset cleared the query. The page checks require workspace initialization, a visible heading or the correct open legal dialog, and no uncaught page errors. Route and control checks establish rendered UI behavior; they do not establish payments or on-chain changes. The same browser sweep observed HTTP 429 responses when navigating through many sections, mostly on `/api/solana/rpc` and `/api/rewards/experience`; these are rate-limit observations, not successful data fetches. The creator support endpoint returned 401 without an authenticated wallet as expected.

The route audit exposed one client bug: `reward-experience-ui.js` fetched the same reward bundle on each hash change, enough to exhaust the endpoint's 30-request-per-minute budget during navigation. `git blame` traces that listener to `de08b076`. The candidate now reuses a refresh for 15 seconds when wallet, token scope, X sign-in, and alert setting are unchanged. Identity and token scope changes still refresh immediately. `tests/browser/reward-route-refresh.spec.js` checks both behaviors with mocked API responses. A post-deployment audit is required to establish the production effect. Solana RPC 429 responses have a separate budget and remain a live limitation.

The existing launch-options browser matrix passed against the public UI with its API response deliberately mocked to 503. The Home active-rewards live verifier passed after opening the current disclosure: 12 launched projects, 1 FUNDED card, 11 coin cards, and no X cards. These establish UI layout and fallback behavior only. Local Chromium regressions use mocked API/RPC fixtures.
